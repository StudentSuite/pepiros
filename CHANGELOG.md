All notable changes to this project are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses [Semantic Versioning](https://semver.org/) once it has a real release — pre-1.0, expect breaking changes without notice.

## [Unreleased]

Still stubbed (see the `TODO` comment at the top of each file): PDF ingestion (`scripts/parse.py`, `scripts/ocr_fallback.py`, `app/api/ingest`), 15 of the 21 node generators plus figure vision, the MCP server (`mcp/*`), graph-mutation endpoints (`app/api/nodes/*`, `/api/compare`), and chat/export/auth. ### Added

- **Design system: Editorial Paper direction, full token set, and a real `components/ui/` primitive library.** Locks the visual direction on top of the existing "lab notebook at night" thesis (Are.na × Instapaper/NYT Reader; brief and canonical palette in `design/DIRECTIONS.md`), reconciles `app/globals.css`/`tailwind.config.ts` with the complete `docs/PLAN-V1.md` §14.2 token set (spacing, radius, elevation, motion durations/easings, layout dims -- previously color/font only), and wires real webfonts via `next/font` (Source Serif 4, Inter, JetBrains Mono replaced a silent Georgia/system-ui fallback that had been rendering since the tokens were first named). `components/ui/` grows from 4 files to a real primitive library: Button, IconButton, Input/Textarea/FormField, Dialog, Drawer, Tooltip, Popover, Tabs, Menu, Toast/Toaster, Skeleton, ErrorBanner, Badge (PillarChip/RefChip/EvidenceBadge consolidated onto it), Icon (Lucide, first icon library in the app), and Logo. Implements the `docs/PLAN-V1.md` §14.3 motion spec and §14.5 state spec everywhere this app has a real trigger for them: canvas node-appear entrance with sibling stagger, the PDF highlight "money shot" animation, the citation-chip 140ms hover popover, contradiction-edge dash-march, and empty/loading/error states across chat, canvas, the reader, and the related-papers rail. Fixes a real a11y gap `docs/PLAN-V1.md` §15 flagged (3 of the 7 canonical pillar hues fell below WCAG AA's 4.5:1 as text against `--surface-raised`) and adds a global `focus-visible` fallback. Adds `app/icon.svg`, `app/apple-icon.tsx`, and `app/opengraph-image.tsx` (no logo/favicon/OG image existed before), and redesigns the landing page grounding-first per the new `docs/PLAN-V1.md` §22 Platform Vision (accounts, publish/auto-graph, discovery, discussion -- additive scope targeting Aug 17 alongside the existing demo, not built this pass). Also fixes a real bug this work's own browser QA surfaced: ghost-citation node/edge ids collided whenever two workspace papers shared an external citation, silently dropping one of the two real edges (`components/canvas/GraphCanvas.tsx`).
- **The LLM layer now runs on Groq (primary) + Featherless (fallback), not Anthropic.** `ai` bumped 4.x -> 5.x to pair with provider packages sharing the same `@ai-sdk/provider` major (2.x); `@ai-sdk/anthropic`/`@anthropic-ai/sdk` removed. `lib/ai/client.ts` resolves each tier through `lib/ai/fallbackModel.ts`'s `withFallback()`: try Groq, and only on a 401/402/403/429 or provider-marked-retryable error -- something specific to Groq or this account on it -- retry the identical call against Featherless (`@ai-sdk/openai-compatible`, no first-party AI SDK provider for it). A malformed-request error (400/404) still surfaces immediately, since a second provider would fail it identically. Either provider works alone if only one key is set.
- Model picks were verified live against real accounts, not guessed or taken from docs alone: on Groq, only `openai/gpt-oss-20b`/`-120b` support the structured outputs every `generateObject` call here needs -- confirmed by an actual 400 from `llama-3.1-8b-instant`, which has a far higher rate limit but can't do schema-mode calls at all; on Featherless, `Qwen/Qwen2.5-7B-Instruct`/`-72B-Instruct` were confirmed with a real authenticated chat completion (meta-llama's repos there are gated behind a HuggingFace org connection and 403 without it).
- `lib/schemas/index.ts`: zod schemas for `PillarPlan` and the uniform `GeneratorOutput` contract (docs/PLAN-V1.md §7-8), plus a `types/anchor.ts` change exporting `PAPER_ARCHETYPES` as a runtime array so the zod enum and the frozen `PaperArchetype` type are built from one source instead of two hand-synced lists (the exact drift already fixed once, per the entry below).
- `lib/prompts/contextBlock.ts`: builds the `[C7 | Methods | p.4]`-style stable-id context block a generator is shown, using the same `ordinal`-based ids `lib/grounding/anchor.ts` resolves -- a generator's citation is guaranteed either resolvable or correctly flagged `hallucinated_ref`, never accidentally valid-but-wrong.
- `lib/agents/archetypeClassifier.ts` and `lib/agents/pillarPlanner.ts`: real, working (fast-tier closed-set classification; strong-tier archetype-conditioned pillar/leaf planning with the anti-template forcing function from docs/PLAN-V1.md §7).
- `lib/agents/generators/`: a shared runner (`runGenerator.ts`, the citation-marker contract every generator shares) plus 6 real generators -- `summary`, `methodology`, `statistical_validity`, `stated_limitations`, `weaknesses`, `does_not_establish` -- chosen because the spec calls out `weaknesses`/`stated_limitations` as collapsing into duplicates without an explicit prompt-level distinction, and `does_not_establish` as a first-class overclaiming guard. `weaknesses.ts` also exports a banned-generic-critique phrase list checked deterministically (`findBannedPhrases`), not just prompted for.
- `lib/agents/orchestrator.ts`: `p-queue` concurrency-4 fan-out with per-node failure isolation (one generator throwing never affects its siblings) and graceful handling of a plan referencing one of the 15 not-yet-implemented generators. Every generator's claimed evidence is re-verified through the existing `lib/services/verify.ts` -- a multi-ref aggregate claim becomes one Evidence row per ref, concatenated into its body_md marker, so a partially-supported aggregate claim keeps its passing citations and drops only the failing one.
- `lib/testing/mockLanguageModel.ts`: a minimal hand-rolled `LanguageModelV2` fake for testing `generateObject` callers without a real API key or network call, and without `ai/test`'s transitive `msw` dependency. 21 new tests across the LLM layer, including one exercising the multi-ref partial-verification path end to end against the real fixture.
- `OPENALEX_MAILTO`/`SEMANTIC_SCHOLAR_API_KEY` (declared in `.env.example`, previously unused) are now actually wired into `citationExpand.ts`/`related.ts` -- both move a caller out of the anonymous rate-limit pool that was observed 503'ing/429'ing earlier.
- `lib/services/related.ts` now throttles to Semantic Scholar's documented keyed-tier limit ("1 request per second, cumulative across all endpoints"): a single `fetchRelatedPapers` call makes two requests (search, then recommendations) with nothing between them, which alone would have violated that. The throttle is process-wide module state, so it also spaces out overlapping calls for different papers, not just the two within one call.
- Repo transferred to the StudentSuite org; all `github.com/AnayDhawan/pepiros` references (README, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, `package.json`) and the git remote updated to `StudentSuite/pepiros`.

- `lib/services/related.ts`: real Semantic Scholar Recommendations API client (free, no key) for the Related Papers rail. Resolves a paper by title search, then fetches recommendations; returns a typed `status` (`ok`/`no_match`/`rate_limited`/`error`) rather than throwing, so a miss or an outage renders an honest empty state instead of silently failing or faking a result.
- `lib/services/citationExpand.ts`: real OpenAlex API client (free, no key) for citation-graph expansion. Resolves a paper by title search, then walks one hop via `referenced_works` (`cites`) or the `cites:` filter (`cited_by`); same typed-status contract as `related.ts`.
- `lib/services/externalFetch.ts`: shared fetch helper for both (timeout, typed error, rate-limit classification) so neither service duplicates that plumbing.
- `GET /api/related` and `GET /api/expand` are now real (previously `501`s); `POST /api/expand` stays `501` since ingesting a selected ghost node needs the (still-stub) ingest pipeline.
- `RelatedPapersRail` fetches live data client-side and renders `no_match`/`rate_limited`/`error` states distinctly instead of the static illustrative cards it previously always showed.
- `GraphCanvas` fetches citation expansion for every paper node (both directions) after the base graph loads and renders results as `GhostCitationNode`s at the canvas edge, wired to the real endpoint; "Add to workspace" now calls the real `POST /api/expand` and surfaces its `501` honestly instead of only logging to the console.
- Vitest coverage for all three new service files, including a live-observed edge case (see Fixed).
- Vitest suite over the grounding spine (`npm test`), wired into CI. The 0.1.0 notes below described the spine as "tested" when no test runner existed; this is that claim made true.
- Repository scaffolding: GitHub issue and PR templates, Dependabot, and a CI workflow running typecheck, lint, test, and build on every push and PR.
- `eslint.config.mjs`. ESLint 9 requires flat config, so `npm run lint` had never been capable of running despite CONTRIBUTING listing it as a merge gate.
- `docs/PLAN-V1.md`, vendored in. Roughly thirty `TODO` comments cite it for the detail they need and it was not reachable from a clone.
- `chunks.ordinal` and `numerics.ordinal`, plus `.editorconfig`, `.nvmrc`, and an `engines` field.

### Fixed

- A generator is instructed to cite a context-block id as the bare token ("C7"), not the full bracketed header ("C7 | Methods | p.4") -- observed a real model return the full header live anyway, despite the prompt. `lib/agents/orchestrator.ts`'s `normalizeRef()` now strips to the leading token before verification regardless of what came back, so this doesn't silently register every affected claim as `hallucinated_ref`.
- `classifyExternalError` only treated HTTP 429 as rate-limited. OpenAlex's anonymous-search tier returns a plain `503` with `Retry-After` when its search cluster is overloaded rather than quota-limiting a specific caller -- observed directly against the live API while building `citationExpand.ts`. Both now classify as `rate_limited`, so the UI gives the same "try again shortly" message either way instead of a generic error.
- A claim asserting a bound (`p < 0.05`) against a source reporting a value inside it (`p = 0.003`) was demoted to `unsupported`. `numericTokenMatchesRow` compared values for equality and ignored the comparator it had already parsed, so exact quotes failed the entailment floor on the phrasing most common in the target corpus.
- Citation ids were assigned from array position, so ingesting a paper renumbered every `C{n}` and silently re-pointed already-written `evidence` rows at different text. They now come from a persisted `ordinal` assigned once at ingest.
- The reverse audit scored every (sentence, chunk) pair with a full Levenshtein pass over whole chunk texts. Imperceptible against the 18KB fixture, minutes against a real corpus. Now pruned with an admissible length-ratio bound, which returns the same best chunk: a 10-sentence audit over 300 realistic chunks went from ~10.3s to ~0.5s.
- `app/api/audit` reached into `lib/grounding/*` directly, breaking the service-layer boundary CLAUDE.md defines. Added `lib/services/audit.ts`.
- Server routes imported `fetchWorkspace` from the client zustand store, pulling a client-state container and the whole fixture into the server bundle. The read moved to `lib/services/workspace.ts`; `lib/store/workspace.ts` re-exports it for client consumers.
- `PaperArchetype` in the frozen `types/anchor.ts` contract listed six archetypes; `lib/agents/archetypeClassifier.ts` specified a different nine. Reconciled on the classifier's set, and the fixture's papers remapped (`meta_analysis` to `systematic_review`, `observational` to `cohort_study`).

## [0.1.0] - 2026-08-05

### Added

- Grounding spine (`lib/grounding/*`): deterministic fuzzy-match quote verification (`token_set_ratio`, no LLM judge), the numeric entailment overlap floor, and citation-ref resolution.
- Data layer: full Drizzle schema across all 18 tables in the plan.md §5 data model, Supabase browser/server/service clients, `drizzle.config.ts`.
- Shared contract: `types/anchor.ts` and a worked `fixtures/workspace.json` (3 papers, a contradiction pair, a cross-paper cites link, and one planted misattribution that the verifier correctly demotes to `unsupported`).
- Full UI: React Flow canvas (5 node types + ghost citation nodes + kind-colored edges), the doc-reader view (default landing surface), outline/audit/learn/canvas/share pages, chat dock, node inspector, flashcards/quiz, numeric charts — all against the "lab notebook at night" dark-first design tokens.
- Real API routes: `POST /api/verify` (single-claim re-verification), `POST /api/audit` (reverse audit — paste external text, sentence-split, verify each sentence against the corpus), `GET /api/graph/[workspaceId]`.
- Placeholder `501` handlers for the remaining `app/api/*` routes that need LLM/job-queue/live-DB infra not yet provisioned, so the app builds cleanly end to end.
- Project documentation: README, CLAUDE.md, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, LICENSE (MIT).

### Fixed

- Entailment-floor check was scoped to a single `Numeric` row instead of every numeric belonging to the resolved chunk — caught via a sanity check against the fixture and fixed before it shipped.
- A `"95% CI ..."` confidence-interval annotation was being treated as its own claimed statistic, causing false `unsupported` verdicts on otherwise-exact quotes; the numeric-token extractor now excludes it.
