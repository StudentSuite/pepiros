## Global Constraints

Copy this whole section verbatim into every implementer and reviewer dispatch.

**Brand: already implemented as tokens, reuse them, never hardcode hex:**
- Base chrome everywhere is dark: `bg-surface` (`#14161a`) / `bg-surface-raised` / `bg-surface-sunken`, text `text-ink` / `text-ink-muted` / `text-ink-faint`. This is the default (`<html class="dark">` in `app/layout.tsx`, already applied); do not add a light/dark toggle, do not add `next-themes`.
- Reading-surface content (hero copy panels, prose, cards, auth forms) uses the `.surface-reading` class (`bg-paper` `#f5f1e8` + dark ink `#1c1a15`) plus the `.paper-grain` class (already-defined SVG-noise texture, no image asset needed) stacked on the same element. Example: `<div className="surface-reading paper-grain rounded-lg p-6">`.
- Pillar colors: `bg-pillar-1`..`bg-pillar-7` / `text-pillar-N` / `border-pillar-N` (Tailwind tokens, already wired to `--pillar-1..7`). Use `pillarColor(index)` / `pillarTextColor(index)` from `components/ui/PillarChip.tsx` when you need the raw CSS value (e.g. inline `style`) instead of a Tailwind class.
- Evidence-tier colors (`located` / `paraphrase` / `unsupported` / `inference` / `ungrounded`) are separate Tailwind color tokens, already wired; use for quote-located/inference badges, never invent new ones.
- Fonts: `font-serif` (Source Serif 4, headings, small-caps labels), `font-sans` (Inter, UI/body, this is the *default* body font already set on `<body>`, no need to add the class everywhere), `font-mono` (JetBrains Mono, ids/scores/numbers). Small-caps section labels: `className="font-mono text-[10px] uppercase tracking-widest text-ink-faint"` (copy the exact pattern already used in `app/(marketing)/page.tsx`'s "Coming soon" label) or `font-serif ... uppercase tracking-[0.2em]` (the Logo wordmark pattern); pick whichever the specific task calls for, stay consistent within a page.
- Motion: only `duration-fast` (170ms) / `duration-base` (280ms) / `duration-slow` (450ms) / `duration-canvas` (590ms) with `ease-out` (never `ease-spring`, that token exists for completeness only, do not reference it). No spring physics, no bounce, ever.
- Spacing: use the `s-1`..`s-8` scale (Tailwind spacing tokens already wired: `p-s-4`, `gap-s-5`, etc.) over ad-hoc Tailwind spacing numbers where a task deals with reading-context content (Editorial Paper's +25% whitespace rule is already baked into how `s-5` etc. are sized relative to a hypothetical `s-4` chrome gap; just use the scale, don't hand-calculate +25%).
- Icons: **only** via `<Icon icon={SomeLucideIcon} size="xs"|"sm"|"md" />` from `components/ui/Icon.tsx`. Never `import { X } from "lucide-react"` and render it raw.
- Banned word: "verified" / "Verified" anywhere in UI copy, including empty/error states and settings. The only correct phrase for a matched citation is "quote located." Two-tier framing is `quote-located` (deterministic) vs `inference` (model-generated); never blur the two.
- Banned patterns (inherited from a sibling project's design system, worth keeping): side-color-stripe borders as a card motif, gradient text, glassmorphism-by-default (backdrop-blur soup), identical repeating card grids with no visual variation, em dashes in copy (use commas/periods/parens).
- Tagline, verbatim where a page needs one: **"Every claim, one click from its source."**
- Positioning rule: the grounding/verification pitch is the headline on every page that touches it (home, how-it-works, mcp). Platform-vision content (accounts, discover, publish, discuss) is always visually smaller/quieter and never the first thing a page says.

**Reuse these existing components as-is, do not recreate:** `components/ui/{Badge,Button,Dialog,Drawer,ErrorBanner,EvidenceBadge,FormField,Icon,IconButton,Input,Logo,Menu,OfflineBanner,Panel,PillarChip,Popover,RefChip,Skeleton,Tabs,Toaster,Tooltip}.tsx`. Key APIs:
- `buttonClassName(variant, size, className)` and `<Button variant="primary"|"secondary"|"ghost"|"danger" size="sm"|"md">` from `components/ui/Button.tsx`: use `buttonClassName(...)` directly on a Next `<Link>` for CTAs (never nest `<button>` inside `<a>`).
- `<Panel padded>` / `<Card padded>` (same component, either name) from `components/ui/Panel.tsx` for chrome-surface containers (not reading-surface, those use `.surface-reading .paper-grain` instead).
- `<Logo tagline variant="chrome"|"paper" />` and `<LogoMark />` from `components/ui/Logo.tsx`: `variant="paper"` when the logo sits on a `.surface-reading` panel, `"chrome"` (default) everywhere else.
- `<PillarChip pillarIndex={n} label="..." />`, `<RefChip refId="C7" />` from their respective files.
- `<Toaster />` and `<OfflineBanner />` are already mounted globally in `app/layout.tsx`; don't remount them per-page.

**Mock data: the whole point of this plan, no real backend:**
- Product-screen tasks (reader/canvas/outline/audit/learn/share consistency passes) keep reading from the existing `fixtures/workspace.json`; do not touch its shape.
- Every new platform/marketing surface that needs list/detail data (discover, paper detail, profile, settings/tokens, workspaces dashboard) reads from a new `lib/mock/` module, one file per domain: `lib/mock/discover.ts`, `lib/mock/paper.ts`, `lib/mock/profile.ts`, `lib/mock/workspaces.ts`, `lib/mock/settings.ts`. Each exports typed plain arrays/objects (no fetch, no async, no Supabase import anywhere in these files) and a couple of typed helper functions (e.g. `getMockPaperBySlug(slug: string)`) that pages call directly (server components can call them synchronously at render time). Auth state (`/login`-adjacent "am I signed in") is a single `lib/mock/session.ts` exporting a hardcoded `mockSession: { user: MockUser } | null`: tasks that need "signed in" vs "signed out" just flip which literal they render from, no cookies/context/provider machinery.
- Forms (login, signup, upload's license checkbox, settings fields) get real client-side validation (required fields, email shape, etc. via plain React state; no react-hook-form/zod dependency added, the repo doesn't have one on the client side for these light forms) but their submit handler does nothing but a client-side transition (e.g. `router.push(...)`, or a local success/error state flip); never a `fetch()` to a real or stubbed API route.
- Do not create any new file under `app/api/`, do not touch `lib/services/`, `mcp/`, `scripts/`, or any Supabase/drizzle code. That is out of scope for every task in this plan.

**Verification, every task:** `npm run typecheck && npm run lint && npm run build` must all pass: this repo has no component-level test suite (only `lib/*` logic tests under `vitest`), so "tests" for a UI task means these three commands, not new test files. Do not add `@testing-library/react` or any new test tooling; out of scope. Describe what a manual `npm run dev` check should show in the report, but the three commands above are what the reviewer will re-derive from the diff.

**Route groups:** `app/(marketing)/` = pure content, no auth-aware chrome. `app/(platform)/` = new group, public pages with auth-aware header (signed-in vs signed-out via `lib/mock/session.ts`). `app/(app)/` = existing, authenticated-only; gets 3 new page directories added to it by Task 9/10, plus consistency-pass edits to its 6 existing screens by Tasks 11-12.
